⚠️ 本版修正一個嚴重迴歸 bug（v24 引入，已上線影響正式站）：

症狀：地圖上所有 114 個標記疊成一條直線，隨意排列在京都到和歌山之間，
      完全脫離正確地理位置，縮放或平移後亂跳。

原因：v24 加地圖名稱標籤時，寫了 el.style.position = 'relative'，
      想讓標籤能以絕對定位貼在標記下方。但這行 inline style 蓋掉了
      MapLibre 自己在 .maplibregl-marker 這條 CSS 規則設定的
      position: absolute —— 那正是 MapLibre 用來把每個標記精準
      定位在地圖經緯度座標上的機制。一旦被蓋掉，標記就變成參與
      一般網頁排版（in-flow layout），於是全部照 DOM 順序疊成一直行。

修正：整行移除。.maplibregl-marker 本身就已經是 position: absolute，
      本來就是子層絕對定位的基準，標籤不需要額外設定。

實測：114 個標記在初始畫面、放大、縮小、平移後，
      與其真實經緯度投影位置的誤差全部 < 1px（次像素等級）。

v25（Android 實機回報：小抄捲到底會出現空白破圖）：
- 症狀：日語小抄捲到最底後繼續往下滑，底部導覽列消失，
  下方露出一大片背景色，看起來像壞掉
- 原因：html/body 沒有鎖住捲動，也沒有設 overscroll-behavior。
  Android Chrome 在內層捲到底時會把捲動「鏈結」到整個頁面，
  整頁被往上推，固定在底部的導覽列就跑出畫面外
- 修正：
  - html/body 設 overflow:hidden 與 overscroll-behavior:none，整頁不再捲動
  - 所有內部捲動區（景點清單、已選、介紹面板、聊天、共享清單、分類頁籤）
    都加上 overscroll-behavior:contain，阻止捲動鏈結
- 實測：捲到最底後再用力下滑三次，頁面捲動量維持 0、導覽列仍在

v23（在日本的可靠性，三個真實風險）：

1. 地圖函式庫改為自架，不再依賴 unpkg CDN
   - 原本從 unpkg 載入 MapLibre。萬一在日本連不到那個 CDN，
     app.js 第一行就會拋錯，導致「整個網站空白」——
     實測：0 個景點、0 個頁籤、日語小抄也打不開
   - 現在放在 vendor/，由 Vercel 自己的 CDN 提供，少一個外部依賴

2. 地圖初始化失敗不再拖垮整個網站
   - 整段包進 try/catch，並在所有用到地圖的地方加上保護
   - 實測：地圖函式庫完全載不到時，114 個景點、9 個頁籤、
     69 句日語小抄、行前準備全部照常可用
   - 地圖區塊會顯示說明，而不是一片空白

3. 景點標記不再等待底圖下載完成
   - 原本 renderMarkers() 放在 map 的 load 事件裡，
     那個事件要等底圖樣式從 openfreemap 下載成功才觸發
   - 底圖載不到（網路不穩、圖磚伺服器異常）時，一個標記都不會出現
   - 標記本來就是 DOM 元素，不需要等樣式。改成立刻繪製
   - 實測：離線狀態下，114 個標記與順序編號全部正常顯示
   - 底圖載入有問題時，地圖上方會顯示提示
