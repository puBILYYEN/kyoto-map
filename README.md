# 京都行程景點地圖

一個純靜態網頁（沒有後端、不用資料庫），用 MapLibre GL JS 顯示京都景點地圖，
依「住宿與交通 / 寺與神社 / 穿搭與藥妝 / 美景 / 精進料理 / 動漫迷陰陽師之旅 /
軍事迷織田信長之旅 / 宇治抹茶體驗之旅」八大分類瀏覽，
點景點看詳細介紹，勾選多個景點後可以一鍵開啟 Google 地圖的大眾運輸路線。

## 系統記錄（網站出問題時）

「已選景點」區塊最下面有「🪵 下載系統記錄（.log）」按鈕（手機在下方「✅ 已選」分頁）。
網站出現怪狀況時按一下，把下載的 `.log` 檔傳給 AI（Claude、Gemini 都可以），
AI 就能從記錄裡看到當時發生了什麼事：哪一步出錯、選點什麼時候被改掉、網路有沒有斷。

- 記錄只存在**這支手機**裡，不會上傳，所以要看誰的問題就用誰的手機匯出。
- 就算網站主程式整個當掉，這個按鈕也還按得到。
- 接手的 AI 請先讀 [`HANDOFF.md`](HANDOFF.md)。

## 用 Ornith-1.5-9B（Ollama + Hermes Agent）接手維修

在自己電腦上用 Ollama 跑 Ornith-1.5-9B、搭配 Hermes Agent 時，**一定要先設好上下文長度**：
Ollama 預設只有 4,096 tokens，Hermes 至少要 64,000，沒設好的話模型會「默默忘記」前面的內容，
不會出現任何錯誤訊息，只會表現得很笨。

1. 讓 Ollama 用 64K 上下文（設完要把 Ollama 完全關掉再重開）：
   - Windows：開 PowerShell 執行 `setx OLLAMA_CONTEXT_LENGTH 65536`
   - macOS：終端機執行 `launchctl setenv OLLAMA_CONTEXT_LENGTH 65536`
   - Linux：`OLLAMA_CONTEXT_LENGTH=65536 ollama serve`
2. Hermes 設定檔 `~/.hermes/config.yaml` 的數字要跟上面一樣（模型名稱用 `ollama list` 顯示的）：
   ```yaml
   model:
     default: ornith-1.5:9b
     provider: custom
     base_url: http://localhost:11434/v1
     context_length: 65536
   ```
3. 本機模型比較慢，建議再設 `HERMES_STREAM_READ_TIMEOUT=1800`（等待上限改成 30 分鐘）。
4. **先用終端機 `cd` 到這個專案資料夾再啟動 Hermes**，它才會自動讀到專案根目錄的 `.hermes.md`
   （9B 快速卡，內容跟 `HANDOFF-9B.md` 一樣）。Hermes 每次只讀一個說明檔，`.hermes.md` 會優先於 `AGENTS.md`。
5. 顯示卡記憶體不夠時，Ollama 會把一部分放到 CPU 上跑，會變慢但還是能用。

沒有任何 build 流程、沒有 package.json，純 HTML/CSS/JS，Vercel 會自動當成靜態網站部署。

## 部署到 Vercel（三種方式擇一）

### 方式一：Vercel 網站拖拉上傳（最簡單，不用裝任何東西）

1. 到 https://vercel.com 註冊 / 登入帳號（可用 Email 或 GitHub 帳號登入）
2. 進入 Dashboard，點右上角「Add New...」→「Project」
3. 選擇畫面上「拖拉檔案上傳」的區域，把整個 `kyoto-map` 資料夾拖進去
   （如果只能選檔案不能選資料夾，改用下面「方式二」）
4. 按下 Deploy，等待約 10～20 秒，就會拿到一個 `https://xxxx.vercel.app` 的網址

### 方式二：用 Vercel CLI（電腦上有 Node.js 的話）

在終端機（Mac 用「終端機」App，Windows 用 PowerShell 或 cmd）裡執行：

```bash
# 1. 安裝 Vercel CLI（只需要做一次）
npm install -g vercel

# 2. 切換到這個資料夾
cd 你解壓縮後的kyoto-map資料夾路徑

# 3. 登入並部署
vercel login
vercel --prod
```

過程中它會問幾個問題，全部按 Enter 用預設值就可以。跑完之後終端機會顯示一個網址，
那就是可以直接貼給家人的連結。

### 方式三：透過 GitHub 匯入（適合之後還想常常修改內容）

1. 把 `kyoto-map` 資料夾建立成一個新的 GitHub repository（可以用 GitHub Desktop 或網頁上傳）
2. 到 https://vercel.com/new，選「Import Git Repository」，選剛剛那個 repo
3. 其他設定都不用改，直接 Deploy
4. 之後如果要修改景點資料，只要改 GitHub 上的 `data.js` 檔案，Vercel 會自動重新部署

## 如何新增或修改景點

打開 `data.js`，裡面是一個叫做 `SPOTS` 的陣列，每個景點長這樣：

```js
{ id:'t62', categories:['temple'], name:'新景點名稱', area:'所在區域',
  lat:35.0000, lng:135.7500, desc:'這裡寫景點特色介紹文字。' }
```

- `id`：不能跟其他景點重複，各分類的開頭字母為 temple 用 t、shopping 用 s、scenic 用 v、
  shojin 用 j、onmyoji 用 o、nobunaga 用 n、ujimatcha 用 u、stay 用 b，數字接續下去即可
- `categories`：**陣列**，可同時屬於多個分類，例如 `['temple','onmyoji']`。
  可用的分類有 `stay`（住宿與交通）、`temple`（寺與神社）、`shopping`（穿搭與藥妝）、
  `scenic`（美景）、`shojin`（精進料理）、`onmyoji`（動漫迷陰陽師之旅）、
  `nobunaga`（軍事迷織田信長之旅）、`ujimatcha`（宇治抹茶體驗之旅）
- `lat` / `lng`：緯度／經度，可以到 Google 地圖上對著該地點按右鍵複製座標
- `address`：**選填**。填了之後，詳細介紹裡的「在 Google 地圖上看」會改用地址去查，
  適合座標只有概略值、但地址確定的地點
- `hours`：**選填**。營業／開放時間，例如 `'9:00–17:00'`。
  有填的話，地圖標籤與景點介紹都會顯示；沒填會顯示「未收錄」並引導看 Google 地圖。
  **不確定就留空** —— 寫錯的營業時間比沒有更糟
- `labelSide`：**選填**。地圖標籤預設貼在標記正下方，填 `'left'` 或 `'right'`
  可以改貼到左邊或右邊——密集區域的景點互相重疊時可以用這個錯開
- `booking`：**選填**。格式為 `{ level:'required', note:'說明文字' }`，
  `level` 可填 `permit`（需事前申請）、`required`（必須預約）、`recommended`（建議預約）。
  填了之後清單會出現標籤，也能用「只看需要預約／申請的景點」篩選出來

另外兩塊內容也寫在 `data.js`，對應右上角的兩個按鈕：

- `TRIP_PREP` → 「🛂 行前準備」：護照、免簽、Visit Japan Web 等證件事項
- `PHRASES` → 「💬 日語小抄」：住宿地址日文寫法、緊急電話、69 句求助日語（10 個分類）

日語小抄每句的格式是 `{ zh: '中文意思', ja: '日文原文', sound: '中文近似發音' }`，
要增減句子直接改 `PHRASES.groups` 裡的陣列即可。這部分是純靜態資料，
**沒有網路也能開**，在日本漫遊訊號不好時仍然可用。
- `desc`：介紹文字，會顯示在下方詳細介紹欄

存檔後重新部署（方式一、二要重新拖拉/執行一次；方式三只要 push 到 GitHub 就會自動更新）。

## 使用說明（給你跟家人）

- 左側可切換分類頁籤，或用搜尋框輸入關鍵字篩選景點
- 點景點名稱或地圖上的圓點，下方會顯示該景點的詳細介紹
- 勾選景點前面的checkbox可以多選，選了兩個以上，左下角會出現「查大眾運輸路線」的按鈕，
  點下去會直接跳到 Google 地圖幫你算好公車/電車路線（依照你勾選的順序，一段一段串起來）
  ※ Google 地圖的大眾運輸模式只支援兩點之間，所以多個景點會拆成一段一段
- 勾選的景點會在地圖上連起來，圓點內標示 1、2、3 的順序，一眼看出動線順不順。
  這條線會貼著實際的道路走（不是直線），比較看得出來實際上要怎麼繞；
  如果你設定了跳棋名字，其他有設定跳棋的家人也會各自用自己的顏色，
  同時顯示他們自己的路線在同一張地圖上
  ※ 這條線是「走路」路徑，不是精確的公車/電車轉乘路線——精確的大眾
  運輸轉乘還是要用下面「查大眾運輸路線」按鈕開 Google 地圖查，那個
  才是真的算過班次的路線；地圖上這條線純粹是給你們「大概怎麼繞」的
  視覺參考
- 已選清單每一列可以按 ▲ ▼ 調整順序、按 ✕ 單獨移除，路線會即時重算
- 路線按鈕上會顯示兩點間的直線距離，上方也會顯示全程直線距離合計，
  方便快速判斷「這兩個點是不是差太遠、不該排在同一天」

路線規劃用的是免費、不需要金鑰的 OSRM 公開示範伺服器（只能算走路路徑，
不是我們自己架的服務），連不上的時候會自動退回原本的直線顯示，不會讓
網站壞掉或卡住。
- 點景點詳細介紹裡的「在 Google 地圖上看」，可以查看照片、評價與營業時間

### 手機上怎麼用（畫面會自動切換成手機版）

螢幕寬度 860px 以下會自動切成手機版，最下方有三個切換鈕：

- **📋 景點清單**：切分類、搜尋、勾選景點
- **🗺 地圖**：看所有景點位置，勾選的點會標上 1、2、3 並用虛線連起來
- **✅ 已選 (n)**：調整順序、開啟各段路線、清除選取

點任一景點會從下方浮出介紹面板，按 ✕ 收起，按「🗺 看地圖」可直接跳到地圖該位置。
Android 的返回鍵會先關閉這個面板，不會一按就離開網頁。
- 目前收錄座標為概略位置，正式排行程或導航前，建議在 Google 地圖上再次確認實際地址與營業時間

## 離線使用（在日本沒訊號時）

網站有 Service Worker（`sw.js`），**只要在有網路時開過一次**，之後沒有網路也能打開：

| 功能 | 沒網路時 |
|---|---|
| 景點清單、搜尋、分類、勾選、路線連結 | ✅ 完全正常 |
| 日語小抄、行前準備 | ✅ 完全正常 |
| 地圖 | ⚠️ 只看得到之前載過的範圍（圖磚有快取，最多 600 張） |
| 線上導遊 | ❌ 需要網路 |

沒有網路時，網頁頂端會出現提示說明。

### 可靠性設計

考量到在日本的網路可能不穩，刻意做了三層防護：

| 萬一 | 結果 |
|---|---|
| 地圖函式庫載不到 | 網站照常運作，只是沒有地圖（會顯示說明） |
| 底圖樣式載不到 | 標記與編號仍然顯示，看得出景點相對位置 |
| 完全沒有網路 | 只要先開過一次，景點、日語小抄、行前準備全部可用 |

地圖函式庫放在 `vendor/`（自架，非 CDN），少一個會掛掉的外部依賴。

**出發前建議做兩件事**：

1. 在有網路的地方把網頁打開一次，並且把地圖縮放到你們會去的區域（嵐山、東山、宇治…），
   讓圖磚先存進快取
2. 用 Android Chrome 開啟後，選單 →「加到主畫面」，之後可以像 App 一樣從桌面開啟

## 用連結分享清單（不需設定，隨時可用）

勾好景點後按「🔗 用連結分享」，會產生一條像這樣的網址：

```
https://kyoto-trip-map.vercel.app/#list=t01,v01,j04
```

用 LINE 傳給家人，對方一點開就載入同一份清單（順序也一樣，因為順序會影響路線）。
手機上會叫出系統分享選單可以直接選 LINE；桌機則複製到剪貼簿。

這條路徑不需要帳號、不需要後端、不花錢，而且**連結本身就是資料**——
在日本網路不穩時也不會因為連不到某個服務而失效。

網址裡的景點代號會逐一比對 `SPOTS`，不存在的代號直接忽略，
所以亂改網址不會讓網頁壞掉。上限 60 個景點，避免網址過長。

## Firebase 設定（跳棋與共同選點需要）

上面的連結分享是「傳一份固定版本給某個人」；如果想要「所有人即時看到彼此
選了什麼、自動整理出大家都想去的景點」，就要設定這個，下面「跳棋」章節
會用到。

> 注意：Firebase SDK 是從 gstatic CDN 動態載入的，
> 網路不穩時可能載不到。在日本現場建議優先用上面的連結分享。

啟用方式：在 Firebase 主控台建立專案 → 加入「網頁應用程式」→ 複製 config，
填進 `data.js` 的 `SHARE_CONFIG.firebaseConfig`：

```js
const SHARE_CONFIG = {
  firebaseConfig: {
    apiKey: '…', authDomain: '…', projectId: '…',
    storageBucket: '…', messagingSenderId: '…', appId: '…',
  },
  tripId: 'kyoto2026',
  maxLists: 30,
};
```

> **這串 config 不是機密**，它本來就會出現在前端原始碼裡，
> Firebase 的設計就是如此。安全性靠的是下面的安全規則。

到 Firestore Database → 規則，貼上這段（把 `kyoto2026` 換成你的 `tripId`）：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trips/kyoto2026/lists/{listId} {
      allow read, delete: if true;
      allow create: if request.resource.data.keys().hasOnly(['name', 'spotIds', 'createdAt'])
                    && request.resource.data.name is string
                    && request.resource.data.name.size() <= 40
                    && request.resource.data.spotIds is list
                    && request.resource.data.spotIds.size() <= 60;
    }
    match /trips/kyoto2026/members/{memberId} {
      // 讀取跟刪除還是開放（刪除要留給「認領舊資料」的搬家流程用，
      // 搬完要清掉舊的、用名字當 ID 的那份），但新增／更新一定要是
      // 本人（Google 登入後 uid 跟文件 ID 一致）才能寫，不會再被
      // 別人打同一個字串蓋掉。
      allow read, delete: if true;
      allow create, update: if request.auth != null
                    && request.auth.uid == memberId
                    && request.resource.data.keys().hasOnly(['name', 'color', 'spotIds', 'updatedAt'])
                    && request.resource.data.name is string
                    && request.resource.data.name.size() <= 10
                    && request.resource.data.color is string
                    && request.resource.data.spotIds is list
                    && request.resource.data.spotIds.size() <= 60;
    }
    match /trips/kyoto2026/memberLogs/{logId} {
      allow read: if true;
      allow create: if request.resource.data.keys().hasOnly(['action', 'memberId', 'name', 'deviceId', 'spotCount', 'at'])
                    && request.resource.data.action in ['sync', 'delete']
                    && request.resource.data.name is string
                    && request.resource.data.name.size() <= 10;
      // 只能新增，不能改、不能刪——這是除錯用的記錄，本來就該是不能事後竄改的
    }
  }
}
```

這組規則把可寫入的範圍限制在這幾個路徑，並檢查欄位與長度。`members` 是「跳棋」功能用的（見下面說明），文件 ID 是 Google 登入後的 uid。`memberLogs` 是跳棋的除錯記錄（見下面「跳棋同步記錄」說明），只能新增、不能修改或刪除。`lists` 集合是舊版「分享清單」功能留下的，目前網站已經不會再寫入，保留規則只是不影響舊資料，不影響新功能。

跳棋改用 Google 登入之後，`members` 的新增／更新一定要是本人（`request.auth.uid == memberId`）才能寫，其他人沒辦法冒充你的身份改你的資料，也不會再有兩個人打同一個字串互相覆蓋的問題。`lists` 沒有登入機制，維持原樣（家庭旅遊用途，知道網址的人可以讀寫，風險可接受）。

### 開啟 Google 登入（跳棋功能必須）

跳棋改成要用 Google 帳號登入，除了上面的 Firestore 規則，還要在 Firebase 主控台做兩件事，缺一個都會讓登入失敗：

1. **Authentication → Sign-in method** → 啟用「Google」這個登入方式（選一個顯示用的專案支援電子郵件即可）。
2. **Authentication → Settings → 已授權網域**（Authorized domains）→ 把網站實際的網域加進去，例如 `kyoto-trip-map.vercel.app`。Firebase 預設只會有它自己的 `*.firebaseapp.com`／`*.web.app`，部署在 Vercel 的網域一定要手動加，不然登入會直接失敗（`auth/unauthorized-domain`）。

沒開這兩個的話，按「🔑 用 Google 帳號登入」會跳出登入失敗的提示，不會讓網站其他功能壞掉。

沒有填 config 的話，按鈕還是可以按，只會顯示「尚未設定」，不會讓網站壞掉。

> ⚠️ **重要**：如果 Firestore 規則已經是舊版（只有 `lists` 那一段），要記得回
> Firebase 主控台 → Firestore Database → 規則，把上面完整的新版貼上去再發布，
> 不然跳棋功能會因為權限被拒絕而完全無法同步（地圖上不會顯示任何錯誤訊息，
> 只是安靜地同步失敗，選點功能本身不受影響）。

## 跳棋（即時顯示每個人選了什麼）

用 Google 帳號登入一次，選點就會自動同步給其他家人看，不用手動傳連結或
按「分享」——地圖上每個人的選點會用自己的顏色、自己的順序號碼顯示成
一顆顆小棋子疊在景點旁邊，不會互相覆蓋掉。

- 身份綁在 Google 帳號上（用登入後的 uid 當 Firestore 文件 ID），同一個
  帳號不管在哪個裝置、哪個瀏覽器登入，都會對到同一份資料、同一個顏色。
  **這個版本已經不會再有「兩個人打了同一個名字互相覆蓋」的問題**——
  這是舊版（打名字當識別碼）曾經真的發生過的 bug，才改成這樣。
- 顏色預設由帳號的 uid 算出固定值，也可以自己在色票裡點選喜歡的顏色，
  會記住、下次登入沿用。
- 「名字」現在只是顯示標籤（預設抓 Google 帳號的顯示名稱，可以自己改），
  跟身份是分開的兩件事：**改名字不會變成新的身份**，就只是換個顯示的
  稱呼，其他家人下次看到的名字會更新，選點資料完全不受影響。
- 這個功能跟上面「用連結分享」是各自獨立的兩套機制：連結分享是傳一份
  固定版本給某個人；跳棋是登入一次之後全自動、即時同步，兩者不會互相
  干擾，可以同時使用。
- 設定好之後那一列旁邊有「🗑️」按鈕，可以刪除自己這個身份（同時會登出），
  例如測試用的帳號想清掉重來時使用；正式使用的帳號不用刻意去刪。

### 從舊版（打名字）搬過來的資料怎麼辦

改版之前用名字設定過跳棋的人（例如「哥」「秀容」「妹妹」），第一次用
Google 帳號登入時，如果偵測到 Firestore 裡還有舊版留下、看起來像是名字
（不是 Google uid）的資料，會先跳出「你是不是下面哪一位？」的選單：

- 選到自己之前用的名字 → 之前選的景點、顏色會直接接過來，不用重選，
  接過來之後那筆舊資料就會被刪除（換成新的、綁在 Google 帳號上的資料）
- 選「都不是，我是新加入的」→ 當作全新身份開始，不會動到任何舊資料

只有第一次登入、而且這個 Google 帳號還沒有自己的資料時才會問；已經
登入過的人下次打開網站會直接恢復原本的身份，不會再跳出這個選單。

### 共同選點

設定好跳棋名字之後，「已選景點」欄位下方會多一塊「🧭 共同選點」，
自動統計目前大家（含自己）選了哪些景點、分別是誰選的，兩人以上重疊
的景點會排在最上面、用比較深的底色標出來，點一下該列還能直接跳到
那個景點的詳細介紹。這是完全自動產生的清單，不用手動存、不用手動
按「開啟」，取代了舊版需要手動存/開的「分享清單」功能。

### 跳棋同步記錄（除錯用）

「🧭 共同選點」下方有個「🔍 查看跳棋同步記錄」按鈕，點開會列出最近
40 筆同步紀錄：時間、裝置代號、名字、動作（同步了幾個景點 / 刪除了
身份）。

會做這個是因為：舊版跳棋沒有登入機制、文件 ID 就是名字本身，曾經真的
發生過兩個裝置打了同一個名字、後寫入的直接覆蓋掉前面資料的狀況，選點
無預警變成 0 個。改成 Google 登入後這個特定問題已經在資料層被 Firestore
規則擋住了（uid 保證唯一），但同步記錄還是留著，方便之後任何「選點怎麼
變這樣」的疑問直接看時間軸：是自己在某個時間點清空了選取（正常現象，
清單自然會顯示 0 個），還是發生了其他非預期的寫入。

這份記錄只會新增、不會被修改或刪除（Firestore 規則已限制），裝置代號
只是隨機產生、存在瀏覽器本機，不是任何形式的身份驗證。

## 長按地圖問路

長按地圖上任一點（約 0.55 秒）會跳出「問路小工具」，用日語幫你問路：

- 長按到既有景點附近 → 問「請問到（景點名）怎麼去」
- 長按到空曠處 → 問「請問這個地方怎麼去」，並在地圖放一個臨時圖釘
  方便比給對方看

按「🔊 播放日語問路」會用手機內建的語音合成朗讀日文，
遇到日本人時直接播放給對方聽，不用自己開口發音。

這個功能純前端實作（`speechSynthesis` 是瀏覽器內建 API），
不需要任何後端或金鑰，離線也能用文字版（只是沒有語音）。
問句範本寫在 `data.js` 的 `ASK_DIRECTIONS`，要加其他問句類型可以照樣式擴充。

## 線上導遊（選用功能）

右上角的「🧭 線上導遊」會開啟聊天視窗，可以問景點特色、請它幫忙排順路的順序、
或是現場遇到的問題。它看得到你目前在地圖上勾了哪些景點。

如果你問的是「推薦/安排/建議地點」這種問題（例如「嵐山有推薦去哪嗎」），
導遊會在回答之後直接把建議的景點加進「已選景點」，不用自己再一個一個去
勾——它只會挑資料庫裡真的存在的景點，不會憑空生出一個不存在的地方；
加錯或不想要的話，跟平常一樣在已選清單裡按 ✕ 移除就好。單純問問題（例如
「清水寺特別在哪」）不會動到你的已選清單。

### 請導遊幫忙排順路的順序

問「幫我把選的景點排成順路的順序」或「幫全家人的路線都排得順路一點」，導遊會提出新的先後順序：

- 網站會先用演算法算出「從飯店出發、直線距離最短」的順序給導遊參考（15 個景點以內保證是最短的），
  導遊再依開放時間、預約時段、用餐、長輩體力，以及大家共同選的景點調整，並說明理由。
- **導遊只能調整順序，不能刪掉你們選的景點。** 就算導遊漏寫了某個景點，網站也會自動保留、
  排在最後面；導遊多寫了你沒選的景點，也不會被加進來。
- 自己的順序：按「✅ 套用這個順序」才會換；套用後可以按「↩️ 改回原本的順序」。
- 家人的順序：因為每個人只能改自己的資料，導遊會產生「📤 傳給哥」這樣的按鈕，
  把連結用 LINE 傳過去，對方點開就會套用（一樣只改順序，他之後自己加的景點也會保留）。

這個功能需要一個後端來保管 AI 金鑰（**金鑰絕對不能寫在這個靜態網站裡**，
任何人按 F12 就看得到）。後端是獨立的專案，部署在 Render，本專案完全不受影響：

```
kyoto-map/            → 純靜態，Vercel 自動部署（根目錄沒有 package.json，不能加）
kyoto-map/ai-backend/ → 後端代理，Render（用 Root Directory 指定這個子目錄）
```

後端放在同一個 repo 的子目錄，用根目錄的 `.vercelignore` 排除，
所以 **Vercel 那邊完全看不到它**，現有的靜態部署不受影響。
部署步驟見 [`ai-backend/README.md`](ai-backend/README.md)。

後端部署好之後，把網址填進 `data.js` 的 `AI_CONFIG.endpoint` 即可，例如：

```js
const AI_CONFIG = {
  endpoint: 'https://kyoto-ai.onrender.com',
  ...
};
```

留空的話按鈕還是可以按，只會顯示錯誤代號，不會讓網站壞掉。

### 導遊的錯誤代號

家人看到的只有一句人話加一個代號，技術細節寫在瀏覽器主控台。

| 代號 | 意思 | 怎麼處理 |
|---|---|---|
| `E1` | 沒有網路 | 正常現象，其他功能仍可用 |
| `E2` | `AI_CONFIG.endpoint` 還沒填 | 填入 Render 網址 |
| `E3` | 連不上後端 | 檢查 Render 服務是否還活著 |
| `E4` | 等太久沒有回應 | 多半是冷啟動，再試一次 |
| `E403` | 來源被擋 | Render 的 `ALLOWED_ORIGINS` 設錯 |
| `E429` | 問太快 | 等一分鐘 |
| `E500` | 後端的 AI 設定不完整 | 檢查 `/healthz` 的 `configured` |
| `E502` | 後端連不到 AI 供應商 | 金鑰或端點網址有誤，看 Render 的 Logs |

> Render 免費方案閒置 15 分鐘會休眠，冷啟動要幾十秒。網頁載入時會自動先敲一次
> 後端的 `/healthz` 把它叫醒，所以通常等你真的要問的時候它已經醒了。
